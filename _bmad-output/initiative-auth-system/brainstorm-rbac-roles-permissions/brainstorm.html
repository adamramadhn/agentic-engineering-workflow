combo · the hinge

The hybrid catalog

Code defines the permission catalog from navigation.ts ids; the DB stores only per-role grants. A new page needs no migration — one idea that quietly solved three different questions from four different rooms.

combo

JSONB on the role row

No join table. One row per role, a permissions JSONB column, trivially read into the me payload and the token.

combo

resource.action keys

Resource = nav page id, so users.view and ask-ai.view drive menu, route, and API guard — one key, three doors.

combo

Verbs per page, not CRUD everywhere

users: view/create/update/delete, ask-ai: view/use, watching: view. CRUD is not forced where it makes no sense.

combo

Proxy stays auth-only

RSC page-level guard plus a strict API re-check; the edge proxy keeps jose and never imports pg — respecting the architecture already there.

combo

Everything rides /api/auth/me

The me payload grows a permissions array; a client PermissionProvider + usePermission() hook gates buttons and filters the sidebar. Zero new endpoints.

…and twelve more combinations from the lattice

  • requirePermission() — a one-line guard at the top of each API handler
  • grouped matrix: rows grouped by page, expandable to verbs, roles as columns
  • preset templates (Viewer / Operator / Manager) on role create
  • wildcard users.* or * for the admin superrole
  • perm_version claim; role edit bumps the version — v2, not a v1 need
  • row-scope as a future suffix: users.view.own
  • duplicate-role button — cheap replacement for role inheritance
  • a central PERMISSIONS guard map per route: one map entry per new API route
  • seed 3 system roles on ensureSchema v3 — secure by default
  • a 403 page with ask-admin-for-access copy and a link home
  • roles keyed by immutable TEXT key — users.role becomes an FK with zero data migration
  • matrix saves via PATCH /api/roles/[key]/permissions with a full-set replace — no diff protocol

interlude · before converging

Ground truth

The coach stopped ideating and re-read the codebase. Five facts pinned the design down — and two loose threads were flagged instead of silently decided.

5 facts · 2 threads

navigation.ts

Exports WORKSPACE_PAGES (home, ask-ai, agent-board) + ADMIN_PAGES (users). Watching is a special WorkspaceRoute; ALL_PAGES is the sidebar source.

proxy.ts

Auth-only and edge-safe (jose, no pg) with hardcoded PROTECTED_PREFIXES. Data authorization intentionally lives in the API layer.

the token

The access JWT already carries a role claim, 15-minute TTL, silent refresh rotation. getSessionUser re-verifies strictly; /api/auth/me already exists.

db.ts

ensureSchema() — an idempotent bootstrap at schema v2, UUID PKs, pg pool. Roles are hardcoded in api/users/route.ts; users.role is TEXT, default Member.

so the quiet breakthrough works

Roles keyed by an immutable TEXT key means users.role becomes an FK untouched — zero data migration, and role renames stay free forever.

open threads, kept open

Watching is not in ALL_PAGES — the catalog must include it explicitly so it can be gated. And Ask AI needs a use verb beyond view; the exact verb set per page is to be confirmed with the user.

the synthesis · one sentence, whole architecture

One resource.action key, from one code catalog, drives the sidebar filter, the page 403, and the API guard — while the DB stores only who-has-what, and only the API is allowed to say yes.

hat one · from act i

No migration for new pages — the catalog is generated in code from navigation ids × per-page verbs, so a new page is one catalog entry, not a schema change.

hat two · from act iv

The matrix as a thin view — the data model and roles API are built as if the matrix exists, so its UI is just a lens over grants. Sequencing risk: gone.

hat three · from act iii

Labels are not keys — keys are code identifiers, forever stable; labels arrive via a label map, i18n-ready without a single key changing.

And two problems dissolved without building anything: propagation — the tokens already expire in fifteen minutes and the client already silently refreshes, so permission changes simply ride the existing mechanism; and the through-line that held all 106 ideas together — UI hiding is cosmetics, the API is the truth, and safety rails are part of the feature, not an afterthought.
