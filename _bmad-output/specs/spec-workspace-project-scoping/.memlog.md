- (direction) User meminta board agent harus mengikuti project saat berganti workspace, bukan menampilkan satu project global.
- (note) Temuan kode: agent-board-view.tsx:38,70 fetch ke /api/projects/prj_default/* hardcoded; app-sidebar.tsx:56-64 workspace hanya useState dengan 3 nama hardcoded dan handler yang cuma setState+toast.
- (note) Temuan kode: api/projects/route.ts:9 memanggil ensureInitialBMadData('prj_default') setiap GET, sehingga seed demo selalu masuk ke prj_default.
- (note) Temuan kode: bmad-monitor-mcp config.json menyimpan satu activeProjectId global; tools.go:198 awm_project_init selalu CreateProject tanpa lookup, sehingga dua sesi CLI di repo berbeda saling menimpa.
- (note) Temuan kode: bmad_tasks.id adalah TEXT PRIMARY KEY global (db.ts:280), bukan composite dengan project_id, sehingga ID task antar-project berpotensi bertabrakan.
- (decision) Cakupan: workspace switcher di web dibuat berfungsi penuh (memilih workspace mengganti data board), bukan hanya scoping di CLI.
- (decision) Kunci identitas workspace: git remote URL sebagai kunci utama, fallback ke workspacePath yang dinormalisasi bila remote tidak ada.
- (decision) prj_default dipertahankan sebagai fallback; tidak ada migrasi destruktif, dan bila workspace-nya cocok maka project itu dipakai ulang, bukan diduplikasi.
- (constraint) Satu kunci identitas workspace memetakan tepat ke satu project; penyelesaian harus deterministik dan idempoten (get-or-create), bukan selalu create.
- (constraint) Data prj_default yang sudah ada (task seed, agent nodes) tidak boleh hilang.
- (constraint) Task ID harus unik secara global karena bmad_tasks.id adalah TEXT PRIMARY KEY tanpa project_id.
- (capability) CAP-1 Workspace switcher web: memilih workspace mengganti task board dan agent tree ke project workspace tersebut, dengan pilihan bertahan antar-reload.
- (capability) CAP-2 Resolusi identitas workspace: sistem memetakan remote URL atau path ke project secara get-or-create dan deterministik.
- (capability) CAP-3 API board ter-scope: tidak ada lagi projectId hardcoded; daftar project dan board berasal dari project yang dipilih.
- (capability) CAP-4 State CLI per-workspace: activeProjectId tidak lagi global tunggal sehingga dua repo paralel tidak saling menimpa.
- (capability) CAP-5 Isolasi data: board, task, agent tree, dan backlog yang ditampilkan hanya milik project aktif.
- (assumption) Workspace pada produk ini bukan konsep multi-tenant terpisah; satu workspace setara dengan satu project di bmad_projects.
- (assumption) Sidebar hanya perlu menampilkan project yang sudah terdaftar; pembuatan project tetap lewat awm_project_init atau POST /api/projects.
- (question) Strategi unik untuk bmad_tasks.id: migrasi ke composite PRIMARY KEY (project_id, id) atau menamai ulang ID dengan prefiks project? Keduanya menyentuh data prj_default yang ada.
- (question) Bila workspacePath berubah (repo dipindah direktori) tetapi remote URL sama, apakah project tetap dianggap sama? Spec mengasumsikan ya lewat kunci remote.
- (event) Self-validate pass 1 (koherensi) lulus: 5 capability masing-masing punya intent+success, 5 non-goal eksplisit, success signal dapat didemonstrasikan dengan dua sesi paralel.
- (event) Self-validate pass 2 (preservasi) lulus: seluruh klaim sumber (3 keputusan user, temuan kode) mendarat di SPEC.md atau companion; tidak ada konten wrapper yang dibuang.
- (note) Companion dibuat: identity-mapping.md (aturan normalisasi + tabel keputusan), brownfield.md (peta file:line termasuk 5 titik hardcode board dan 9 titik fallback CLI), architecture-diagrams.md (4 mermaid).
- (decision) Open question 1 dijawab: bmad_tasks migrasi ke composite PRIMARY KEY (project_id, id), bukan prefiks ID. Alasan: tidak merusak pemanggil yang memakai taskId apa adanya (TASK-101 tetap valid per project) dan FK dari bmad_agent_nodes bisa ikut composite karena tabel itu sudah punya project_id.
- (decision) Keputusan yang sama berlaku untuk bmad_agent_nodes.id dan bmad_backlogs.id. Node ID dilaporkan agent sebagai 'agent-analyst-1' dan hampir pasti bertabrakan lintas project, jadi kelas bug yang sama.
- (decision) FK bmad_agent_nodes.task_id menjadi composite (project_id, task_id) REFERENCES bmad_tasks(project_id, id) ON DELETE CASCADE, bukan SET NULL. Composite FK tidak bisa SET NULL karena akan ikut mengosongkan project_id yang NOT NULL. Konsekuensi: menghapus task menghapus node-nya — diterima karena node adalah catatan progres milik task.
- (decision) FK self-reference bmad_agent_nodes.parent_id ikut menjadi composite (project_id, parent_id) REFERENCES bmad_agent_nodes(project_id, id).
- (note) Migrasi PK kompatibel PostgreSQL 18.6 (terverifikasi dari server): ALTER TABLE ... DROP CONSTRAINT ... , ADD PRIMARY KEY (project_id, id) berjalan dalam satu transaksi tanpa rewrite penuh. Data eksisting sudah unik global sehingga tidak ada konflik.
- (decision) Open question 2 dijawab user: belum ada project real, semuanya masih dummy. Karena itu tidak ada UI peringatan tambahan; workspace tanpa project menampilkan board kosong dan prj_default tetap project default yang di-seed.
- (note) Temuan di luar scope: empat tool MCP (awm_backlog_create, awm_backlog_list, awm_backlog_report_impact, awm_backlog_promote) memanggil /api/projects/{id}/backlogs dan /backlogs/{id}/impact, tetapi route itu tidak ada di src/app/api — hanya tabel bmad_backlogs yang dibuat. Semua tool backlog akan 404.

- (event) Self-validate pass 2 (preservasi) lulus pasca-update: jawaban user atas 2 open question dan 3 keputusan turunan (composite key, FK CASCADE, unique index) semuanya mendarat di SPEC.md atau companion.
- (decision) Story breakdown: 5 story. Urutan: schema -> identitas -> API -> switcher -> CLI. Alasan urutan: schema harus ada sebelum API menulis dengan kunci baru; API harus benar sebelum UI memakainya; CLI memakai API yang sudah benar.
- (decision) Story 1: fondasi schema - composite PK (project_id,id) untuk bmad_tasks/bmad_agent_nodes/bmad_backlogs, FK task_id jadi composite CASCADE, FK parent_id composite, unique index pada bmad_projects. Menutup CAP-5.
- (decision) Story 2: resolusi identitas get-or-create - normalisasi remote/path di satu fungsi bersama, POST /api/projects tetap create murni, jalur resolusi baru. Menutup CAP-2.
- (decision) Story 3: API board ter-scope - hapus default parameter prj_default di bmad.ts, hentikan seed pada GET /api/projects. Menutup CAP-3.
- (decision) Story 4: workspace switcher berfungsi - daftar project dari bmad_projects, state project aktif, rebind polling, lima titik hardcode termasuk dua jalur mutasi. Menutup CAP-1.
- (decision) Story 5: state per-workspace di CLI di repo terpisah /Users/adamramadhan/Projects/bmad-monitor-mcp - peta workspaceProjects + satu fungsi resolve menggantikan sembilan fallback. Menutup CAP-4.
